1. What are you building?

Imagine that your group is a small software development company. Your client wants an interactive website that helps learners see how an Operating System manages processes, CPU time, and memory.

Your goal: Build a working application where a user enters values, runs an algorithm, sees the result, and understands why the result happened.

Important: Whichever project you choose, your application must contain three working core modules: resource management, CPU scheduling, and paging. Your chosen project is the feature you explore in more detail.

Use VS Code with Codex, Claude, or Google Antigravity. AI can help write code, but your team must test and explain what it does.

2. Choose ONE project

Discuss the options with your team. Select the main feature you want to develop. You may propose another Operating Systems project with instructor approval.

1

CPU Scheduling Visualizer

Enter processes and compare FCFS, SJF, Round Robin, and Priority. Show a Gantt chart and waiting/turnaround times.

2

Memory Management Simulator

Enter a page reference string and frame count. Compare FIFO and LRU; display frames, hits, and page faults.

3

Smart OS Resource Manager

Build a dashboard that combines process execution, CPU allocation, and memory management.

4

Deadlock Detection Simulator

Show which processes hold or request resources, and visualize possible deadlock situations.

5

Process and Thread Visualizer

Show process states, transitions, and examples of concurrent execution.

6

Disk Scheduling Simulator

Enter disk requests and compare FCFS, SSTF, SCAN, and C-SCAN disk-head movements.

Example: If you choose Disk Scheduling, disk scheduling is your main feature, but you still need the three core modules listed above. Do not submit only a disk scheduling page.

3. Follow these steps in order

1

Form your group and select your project

  • Work in a group of four and agree on one project.
  • Write the problem you are solving and who will use the application.
  • Divide responsibilities: interface, algorithms, testing, documentation/presentation. Everyone must understand the full project.
Output: A project title, short objective, and task allocation.
2

Plan the website before coding

  • Draw a simple layout: Home, Resource Management, CPU Scheduling, Paging, and Your Main Feature.
  • For each module, list the user inputs, calculations, and displayed results.
  • Decide which programming language and website framework to use.
Output: A basic screen plan and feature list.
3

Open VS Code and use an AI coding assistant

  • Create a project folder and open it in VS Code.
  • Use Codex, Claude, or Google Antigravity to generate the first version.
  • Ask for one feature at a time; review the files and run the code.
  • Save at least five meaningful prompts and record what changed.
Create a responsive Operating Systems learning website with four sections: resource management, CPU scheduling, paging, and a project-specific feature. Allow users to enter inputs and run algorithms. Explain the results in simple English. Start with a working HTML, CSS, and JavaScript version.

This prompt is a starting point, not a substitute for checking and improving the generated code.

Output: Your first working application.
4

Build and explain the three required modules

  • Resource management: show processes competing for a resource, how it is allocated, and which processes are waiting.
  • CPU scheduling: implement suitable scheduling algorithms and show waiting time, turnaround time, and a Gantt chart or timeline.
  • Paging: implement and compare page replacement techniques such as FIFO and LRU; show frames and page faults.
  • Then improve your selected project's main feature.
Output: A complete application with real calculations, not only static pictures.
5

Test with at least three different scenarios

  • Use different process arrivals/burst times, page strings, or resource requests.
  • Write down the input, expected answer, actual answer, and whether the test passed.
  • Check at least some results manually or against a trusted worked example.
  • Fix errors and test again.
Example test record: Module: FIFO paging · Input: pages 1, 2, 1, 3 with 2 frames · Expected page faults: 3 · Actual: 3 · Result: PASS.
Output: Three documented test cases with verified results.
6

Upload the code to GitHub and publish the site

  • Create a GitHub repository and upload your source code.
  • Add a README explaining how to run the application.
  • Publish a live website: GitHub Pages for static HTML/CSS/JavaScript, or an appropriate host for a Python/Streamlit app.
  • Open the published URL on another device or in a private browser window and check that it works.
Output: A working GitHub link and a working public website link.
7

Prepare the five-page PDF and slides

Use the exact page-by-page report guide below. Make your slides clear, with screenshots and results rather than long paragraphs.

Output: Exactly five report pages and 8–10 presentation slides.
8

Submit and demonstrate your work

  • Submit the required project materials and links through the LMS/Turnitin by the deadline.
  • Open your website and run real examples during the presentation.
  • All four members should explain their contributions and answer technical questions.
Output: Final submission and a successful live demonstration.

4. What goes in the five-page report?

The official assessment requires exactly five pages of documentation. This page-by-page structure is a suggested way to organize those five pages clearly.

PageWhat to include
1Project title, all four students, problem, objectives, and Operating Systems concepts.
2Tools used, AI assistant, system design, and a simple architecture diagram.
3Features, implemented algorithms, screenshots, and explanation of results.
4At least five AI prompts: purpose, generated output, verification, and improvements.
5Three test cases, results, challenges, improvements, GitHub/live links, and individual contributions.

Presentation: 8–10 slides

Show the project idea, application architecture, core algorithms, a live demonstration, test results, examples of AI prompts, and the GitHub/live website. Every member must participate.
