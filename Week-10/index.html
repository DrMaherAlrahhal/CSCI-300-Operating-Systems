Key idea: The OS must decide what to load, what to keep, what to replace, and how to use limited physical memory efficiently.

1. Demand Paging

Question: Must every page of a program be loaded into RAM before the program starts?

No. Demand paging loads a page when it is needed. If the requested page is absent from RAM, a page fault occurs. The OS retrieves the page from storage (or another backing source), updates the page table, and resumes the instruction.

Connection: Once many pages are requested, RAM may fill up. What should the OS do next?

2. Copy-on-Write (COW)

After a process is created using a mechanism such as fork(), the parent and child can initially share physical pages. If one process writes to a shared page, the OS creates a private copy for that writer. This saves memory when pages are only read.

Connection: Copy-on-write reduces unnecessary copying. But RAM can still become full when new pages are needed.

3. Page Replacement

When no free frame is available, the OS may need to evict a page to make room for another. Page-replacement algorithms decide which page to remove.

FIFO

Remove the page that entered memory first.

LRU

Remove the page that has not been used for the longest time.

Optimal (OPT)

Remove the page whose next use is farthest in the future. Useful as a theoretical benchmark.

Connection: Replacement decides which page leaves RAM. Frame allocation decides how much RAM each process receives.

4. Allocation of Frames

The OS divides available physical frames among processes. Equal allocation gives the same number of frames to each process; proportional allocation can consider process size. Allocation policies affect page-fault behavior.

Try it: Share 12 frames between two processes

Connection: Giving too few frames to active processes can cause frequent page faults.

5. Thrashing

Thrashing happens when the system spends excessive effort handling page faults and moving pages instead of doing useful work. It often occurs when active processes do not have enough frames for their working sets.

Connection: One way to relieve memory pressure is to reduce how much physical space data occupies.

6. Memory Compression

Memory compression stores some memory contents in compressed form so they occupy fewer bytes. This may reduce disk swapping, but compression and decompression use CPU resources.

7. Allocating Kernel Memory

The kernel needs memory for objects such as process records, buffers, and other internal structures. Kernel allocators may use buddy allocation (splitting and combining power-of-two blocks) and slab allocation (reusing preallocated objects).

Remember: Buddy = manage blocks of different sizes. Slab = efficiently allocate and reuse objects of a particular type.

Complete picture

Page requested→Page fault if absent→Find free frame or replace page→Update mapping→Continue execution

The OS also decides how frames are shared, limits thrashing, may compress memory, and allocates memory for its own kernel objects.

3 Exam-style questions

1. Explain demand paging and describe what happens during a page fault.

Demand paging loads a page only when needed. If a process accesses a valid page not currently in RAM, a page fault occurs. The OS locates the page, obtains a free frame or replaces a page, loads the required page, updates the page table, and restarts the interrupted instruction.

2. Compare FIFO and LRU page replacement. Why might LRU perform better?

FIFO evicts the page loaded earliest. LRU evicts the page that was used least recently. LRU may perform better when recently used pages are likely to be reused, but it requires tracking page use. Neither algorithm is best for every workload.

3. What is thrashing, and how can an OS reduce it?

Thrashing occurs when excessive page faults and page transfers leave little time for useful execution. The OS can reduce it by giving processes enough frames for their working sets, reducing the number of competing processes, or using other memory-management techniques where appropriate.
