Week 2 · Revision

What Did We Learn This Week?

In Week 2, we learned how a program works with the Operating System. Imagine you write a C program in VS Code. First, the compiler translates your code, the linker creates an executable file, and the loader prepares it in memory so it can run. While the program is running, it needs help from the OS to open files, use devices, and manage resources. These are called OS services, and the program requests them through system calls. We also learned about system programs, such as File Manager and Terminal, which help us use the computer. Finally, we explored OS design, which explains how the OS should work, and OS structure, which explains how its different parts are organized to work together.

Important Terms to Remember

1. Compiler

A compiler translates source code into object code. For example, it translates a C program written in VS Code.

2. Linker

A linker combines object files and required libraries to create an executable program that can be loaded and run.

3. Loader

A loader prepares an executable program in RAM so the CPU can start executing its instructions.

4. Operating System Services

OS services are functions provided by the Operating System to help applications run, manage files, use devices, and share resources.

5. System Calls

A system call is a request from a program to the OS kernel. For example, a program uses a system call to open or read a file.

6. System Programs

System programs are ready-made tools that help users interact with the computer, such as File Manager, Terminal, and System Information.

7. OS Design

OS design is the process of planning how the Operating System should work to provide good performance, security, and reliability.

8. Policy and Mechanism

A policy decides what should happen, such as which process runs next. A mechanism determines how it happens, such as switching the CPU to that process.

9. OS Implementation

OS implementation means writing and testing the programming code needed to build the Operating System according to its design.

10. OS Structure

OS structure describes how the different parts of an Operating System are organized. Common structures include Monolithic, Layered, Microkernel, and Modular.

Remember the Complete Journey

Write Code → Compiler → Linker → Loader → Run Program → System Calls → OS Services

The Operating System uses its design and structure to manage these activities and help programs work correctly.

Exam preparation

Three important exam questions

Think first. Then click to reveal a suggested answer.

1. Explain the difference between OS services and system calls, using an example.

  • An OS service is a function provided by the OS, such as file management.
  • A system call is the controlled interface used by a program to request certain services.
  • Example: When a C program opens a file, it can use an OS system-call interface to request access; the kernel handles the request and returns a result.

2. Explain the journey of a C program from source code to execution.

  • The programmer writes C source code.
  • The compiler translates it into object code.
  • The linker combines object files and required libraries into an executable.
  • The loader prepares the executable in memory.
  • The OS starts a process and the CPU executes its instructions.

3. Explain the difference between OS design and OS structure, including policy and mechanism.

  • Design decides goals, responsibilities, and how the OS should work.
  • Structure describes how components are organized, such as layered or microkernel structures.
  • Policy decides what should happen (which process runs next).
  • Mechanism defines how it happens (performing a context switch).

Week 2 in one sentence

We write and build a program, the OS loads and runs it, system calls request OS services, and OS design and structure determine how those services are delivered.
