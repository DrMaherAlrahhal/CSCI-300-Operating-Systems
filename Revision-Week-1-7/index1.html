Week 1 · Writing Question 1

Introduction to Operating Systems

Q1. Why does a computer need an Operating System?

Situation: A student turns on a laptop and opens Google Chrome to browse the internet.
Writing Question: What is an Operating System? Explain three things it does to help the student use the laptop.

Model Answer – Read and Understand

An Operating System (OS) is the main software that controls a computer and helps users run applications. Windows, Linux, and macOS are examples.

Runs applications: An application is a program used for a task. Chrome is an application for browsing websites. The OS helps it open and run.

Manages the CPU: The CPU (Central Processing Unit) is the part of a computer that executes instructions. The OS decides which running program gets CPU time.

Manages RAM: RAM (Random Access Memory) is temporary memory used by running programs. The OS gives applications the memory they need.

Example: When Chrome opens, the OS helps it run, gives it CPU time, and provides RAM.

Easy to remember: The OS runs applications and manages CPU, RAM, storage, and devices.

Week 2 · Writing Question 2

OS Services and Structure

Q2. How does the Operating System help save a file?

Situation: A student writes a document in Microsoft Word and clicks Save.
Writing Question: Explain how the application asks the Operating System to save the document.

Model Answer – Read and Understand

An application is a program used for a task, such as Microsoft Word for writing.

Step 1: The student clicks Save. The application needs to store the document.

Step 2: The application makes a system call. A system call is a request asking the OS to perform a service.

Step 3: The kernel, the central part of the OS, handles the request.

Step 4: The OS checks whether the application is allowed to save the file.

Step 5: If allowed, the OS writes the document to storage, such as an SSD, where files remain after shutdown.

Easy to remember: Application → System call → OS kernel → Storage.
Application→System Call→OS Kernel→Storage

Week 3 · Writing Question 3

Processes

Q3. What happens when a student opens and closes a program?

Situation: A student opens Calculator, uses it, and closes it.
Writing Question: What is a process? Explain its five main states using the calculator.

Model Answer – Read and Understand

A program is a set of instructions stored on a computer. A process is a program that is currently running.

New: The OS is creating the calculator process.

Ready: The calculator can run but is waiting for CPU time.

Running: The CPU is executing the calculator’s instructions. The CPU is the part that executes instructions.

Waiting: The calculator is waiting for an event, such as keyboard input.

Terminated: The calculator process has finished after it is closed.

The OS manages when each process gets CPU time. A process can move between Ready, Running, and Waiting more than once.

Easy to remember: A process is a running program. States: New, Ready, Running, Waiting, Terminated.
New→Ready→Running→Waiting / Terminated

From Waiting, a process may return to Ready and run again.

Week 4 · Writing Question 4

Threads and Concurrency

Q4. How can one application perform more than one task?

Situation: A music application plays a song while the student searches for another song.
Writing Question: What is a thread? Explain how multiple threads help the music application.

Model Answer – Read and Understand

A process is a running program. A thread is a smaller unit of execution inside a process. Threads in the same process share memory.

Thread 1: Plays music. Thread 2: Searches for another song.

Multithreading means using multiple threads in one process.

Concurrency means tasks make progress during the same period. They may take turns using one CPU core.

Parallelism means tasks run at the same time on separate CPU cores. A CPU core is a processing unit that executes instructions.

Multiple threads can help the music application respond to the student while music continues.

Easy to remember: A thread is a unit of execution inside a process. Threads help one app handle different tasks.

Week 5 · Writing Question 5

CPU Scheduling

Q5. How does the computer decide which program uses the CPU first?

Situation: Three jobs arrive in order A, B, C. A needs 6 minutes, B needs 2 minutes, and C needs 4 minutes. For SJF, assume all three are ready when scheduling begins.
Writing Question: Explain FCFS, SJF, and Round Robin using these three jobs.

Model Answer – Read and Understand

CPU Scheduling is how the OS chooses which ready process (a running program waiting for CPU time) uses the CPU next.

FCFS (First-Come, First-Served): Run in arrival order. Here: A → B → C.

SJF (Shortest Job First): Run the job needing the shortest CPU time first when all are ready. Here: B → C → A (2, 4, 6 minutes).

Round Robin (RR): Each ready process takes a turn. A time quantum is the fixed CPU time allowed for each turn.

Example: With a 2-minute quantum, A runs for 2 minutes, then B for 2 minutes, then C for 2 minutes. Unfinished jobs wait for another turn.

Easy to remember: FCFS = arrival order. SJF = shortest job first. Round Robin = taking turns.

Week 6 · Writing Question 6

Advanced CPU Scheduling

Q6. How does a robot choose which task is more important?

Situation: A robot reads a sensor every 10 ms, controls a motor every 20 ms, and updates a display every 40 ms.
Writing Question: What is Rate-Monotonic Scheduling (RMS)? Which task has the highest priority, and why?

Model Answer – Read and Understand

RMS (Rate-Monotonic Scheduling) is a method that gives fixed priorities to tasks that repeat regularly.

A task is a job the computer performs. A periodic task repeats at regular times.

A period is the time between the starts of two consecutive occurrences of the same task. ms means milliseconds; 1 ms is one-thousandth of a second.

A priority tells the OS which ready task should run first.

RMS rule: Shorter period = higher priority.

Order: Sensor (10 ms) = highest; Motor (20 ms) = second; Display (40 ms) = lowest.

Easy to remember: RMS: The task that repeats more often (shorter period) gets higher priority.
Sensor · 10 ms · Highest→Motor · 20 ms→Display · 40 ms

Week 7 · Writing Question 7

Process Synchronization

Q7. Why do we need a Mutex and a Counting Semaphore?

Situation: Problem A: Three threads try to update one shared student record. Problem B: Five students want to use four lab computers.
Writing Question: Explain a mutex and a counting semaphore. Choose one for each problem.

Model Answer – Read and Understand

Synchronization means controlling how threads or processes share resources so they do not interfere with one another. A shared resource is something more than one task needs, such as a file or a computer.

Problem A — Mutex: A mutex is a lock that lets only one thread enter a protected part of a program at a time.

One thread updates the student record; the other threads wait. When the first thread finishes, it releases the mutex.

A race condition is an incorrect result caused when tasks access shared data without proper control. The mutex helps prevent this.

Problem B — Counting semaphore: A counting semaphore is a counter that limits access to a number of available resources.

There are four computers, so the semaphore starts at 4. Four students can each reserve one computer. The fifth waits when the counter reaches 0. When someone releases a computer, a waiting student can use it.

Easy to remember: Mutex = one thread at a time. Counting semaphore = limited number at a time.
