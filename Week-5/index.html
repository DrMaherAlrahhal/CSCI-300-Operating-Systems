1 · Basic Concepts

Who gets the CPU next?

A CPU scheduler selects a ready process or thread to execute on a CPU. A ready queue holds tasks waiting for CPU access. A dispatcher performs the switch to the selected task.

Non-preemptiveOnce a task gets the CPU, it keeps it until it finishes its CPU burst or blocks.
PreemptiveThe OS can interrupt a running task and give the CPU to another ready task.

2 · Scheduling Criteria

How do we evaluate a scheduler?

CPU UtilizationKeep the CPU busy. Higher is generally better.
ThroughputNumber of tasks completed per unit of time. Higher is better.
Turnaround TimeCompletion time − arrival time. Lower is better.
Waiting TimeTotal time a task waits in the ready queue. Lower is better.
Response TimeFirst CPU start − arrival time. Lower is better for interactive systems.
Think: For a music app responding to a Play button, would you prioritize low response time or maximum throughput? Answer: Low response time matters most to the user.

4 · Thread Scheduling

Do threads also need scheduling?

Yes. A process can contain several threads. On a single CPU core, runnable threads must share execution time. The OS ultimately schedules kernel-level threads onto available CPU cores.

Process-contention scope (PCS)A user-level thread library chooses which user thread runs on an available kernel thread within a process. Applicable to models with user-level thread scheduling.
System-contention scope (SCS)The kernel chooses among runnable kernel threads across the system to run on CPU cores.

Week 5 · Revision

Week 5 Summary — What Did We Learn?

What Did We Learn This Week?

In Week 4, we learned that a process can have several threads. In Week 5, we learned how the Operating System decides which ready process or thread should use the CPU. Imagine Chrome, VS Code, and Spotify are waiting to run on one CPU core. The ready queue holds their tasks, the CPU scheduler chooses who runs next, and the dispatcher gives that task the CPU. Different algorithms, such as FCFS, SJF, and Round Robin, make different choices. We compare them using waiting, turnaround, and response times to find a suitable algorithm. We also learned that threads need scheduling, not only processes.

Important Terms to Remember

1. CPU Scheduling

CPU scheduling decides which ready process or thread runs next. It helps many tasks share CPU time.

2. Ready Queue

The ready queue holds tasks that are prepared to run but waiting for the CPU. For example, Chrome may wait while VS Code is running.

3. CPU Scheduler

The CPU scheduler chooses the next task from the ready queue. Different scheduling algorithms can choose different tasks.

4. Dispatcher

The dispatcher gives CPU control to the selected task. It performs the switch needed to start or resume execution.

5. Preemptive and Non-preemptive Scheduling

Preemptive scheduling can interrupt a running task. Non-preemptive scheduling lets it keep the CPU until its CPU burst ends or it blocks.

6. FCFS (First-Come, First-Served)

FCFS runs tasks in the order they arrive. A long task can make shorter tasks wait.

7. SJF (Shortest Job First)

SJF runs the task with the shortest available CPU burst first. It can reduce average waiting time when burst lengths are known.

8. Round Robin (RR)

Round Robin gives each ready task a short turn called a time quantum. It helps interactive tasks get CPU time regularly.

9. Scheduling Criteria

We evaluate scheduling using CPU utilization, throughput, turnaround time, waiting time, and response time. Good scheduling depends on the system's goals.

10. Thread Scheduling

Threads also need CPU time. The kernel schedules kernel-level threads, while some thread libraries also choose among user-level threads.

11. PCS and SCS

Process-contention scope (PCS) selects user threads within a process when supported. System-contention scope (SCS) selects kernel threads across the system.

Exam practice

3 Short-Answer Questions

1. Explain CPU scheduling and the difference between preemptive and non-preemptive scheduling.

Answer: CPU scheduling selects a ready process or thread to run on the CPU. In non-preemptive scheduling, the running task keeps the CPU until it finishes its CPU burst or blocks. In preemptive scheduling, the OS may interrupt it to let another task run.

2. P1, P2, P3 arrive at time 0 with CPU bursts of 6, 3 and 8. Calculate FCFS average waiting time.

Answer: FCFS order: P1 (0–6), P2 (6–9), P3 (9–17). Waiting times: P1 = 0, P2 = 6, P3 = 9. Average = (0 + 6 + 9) / 3 = 5 time units.

3. Compare FCFS, SJF and Round Robin. Which is often more suitable for interactive systems, and why?

Answer: FCFS follows arrival order; SJF selects the shortest available burst; Round Robin rotates ready tasks using a time quantum. Round Robin is often suitable for interactive systems because tasks can receive CPU access without waiting for another long task to finish. The quantum size and context-switch overhead matter.
