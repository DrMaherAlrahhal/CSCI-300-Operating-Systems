1. Application I/O Interface

Applications need a consistent way to request input and output. The application I/O interface provides operations such as opening, reading, writing, and closing files, without requiring the application to control the storage hardware directly.

Example: VS Code saves notes.txt. It requests a write operation; the OS handles the hardware-specific details.

2. Kernel I/O Subsystem

The kernel coordinates I/O operations for many applications and devices. Important functions include I/O scheduling, buffering, caching, spooling, and error handling.

Buffering

Temporarily holds data while it is transferred between components.

Caching

Keeps frequently used data for faster access.

Spooling

Queues work for a device, such as print jobs.

Error handling

Detects and responds to failed I/O operations.

3. Transforming I/O Requests to Hardware Operations

A program makes an I/O request. The OS passes it through the appropriate software layers. A device driver communicates with the device controller, which operates the hardware. When the operation completes, the system reports the result back to the application.

Important distinction: A device driver is software; a device controller is hardware. They work together to operate the physical device.

Some I/O is a continuous stream of data rather than a single file operation. This leads to STREAMS.

4. STREAMS

STREAMS is a framework used in some UNIX-derived systems to build communication paths using connected processing modules. Data can move between an application and a device through a stream head, optional modules, and a driver.

5. I/O Performance

I/O performance depends on factors such as latency (delay before an operation completes), throughput (amount of data transferred per unit of time), device speed, request patterns, and OS overhead. Buffering, caching, and efficient scheduling can improve performance in appropriate situations.

Three Exam-Style Questions

1. Explain how an application I/O request reaches a storage device.

An application requests an I/O operation through the OS interface. The kernel processes the request and uses a device driver to communicate with the device controller. The hardware performs the operation, and the result is returned to the application.

2. Describe buffering, caching, and spooling with examples.

Buffering temporarily holds data during transfer. Caching stores frequently used data for faster access. Spooling queues jobs for a shared device, such as a printer. These mechanisms help the OS coordinate I/O efficiently.

3. What is STREAMS, and how can an OS improve I/O performance?

STREAMS is a framework in some UNIX-derived systems that organizes communication using a stream head, optional modules, and a driver. I/O performance can be improved through appropriate caching, buffering, scheduling, and reducing unnecessary device operations. Latency and throughput are important measures.
