1. The Security Problem

Computers hold files, passwords, and important data. The security problem is protecting these resources from unauthorized access, misuse, modification, and disruption.

ConfidentialityOnly authorized people can read data.
IntegrityData should not be changed without authorization.
AvailabilitySystems and information remain usable when needed.

2. Program Threats and System/Network Threats

Program threatsMalicious code such as a Trojan horse, virus, or logic bomb can misuse a program or its privileges.
System threatsAttacks may attempt to exhaust resources, gain unauthorized privileges, or disrupt system operation.
Network threatsAttackers may intercept communications, impersonate a party, or overwhelm network services.

3. User Authentication

Authentication checks a user's identity. Authorization decides what that identified user may do. They are not the same.

4. Goals and Principles of Protection

Protection defines and enforces rules for accessing OS resources, including files, memory, devices, and processes.

Least privilegeGive a user or program only the permissions needed for its task.
Complete mediationCheck access requests against the applicable protection rules.
Separation of privilegeFor sensitive actions, require more than one independent condition when appropriate.
Fail-safe defaultsDefault to denying access unless it is explicitly allowed.

5. Protection Rings and Domains of Protection

Protection rings describe levels of privilege. In a common simplified model, the kernel has higher privilege than ordinary applications. Actual ring usage varies across architectures and OS designs.

Kernel
Highest privilege

Outer area: less privileged execution, such as ordinary user applications.

A protection domain is the set of resources and operations that a process or user is permitted to access. A process should operate within the permissions of its current domain.

An access matrix represents which subjects (users or domains) can perform which operations on objects (resources). Rows are subjects, columns are objects, and each cell contains permissions.

Exam Practice — 3 Questions

Question 1

Explain the difference between authentication and authorization. Give one OS-related example.

Authentication verifies identity, for example checking a student's password. Authorization checks what the authenticated student is allowed to do, such as reading a course file but not editing another student's grades.

Question 2

What is the principle of least privilege, and why is it important for OS protection?

Least privilege means giving each user or program only the permissions necessary for its work. It reduces accidental damage and limits what compromised software can access. For example, a notes viewer should not receive permission to modify protected system files.

Question 3

Use an access matrix to explain how an OS can allow one user to read a file while preventing another user from modifying it.

An access matrix has subjects as rows and objects as columns. A cell lists permitted operations. For example, the Student–Notes.txt cell might contain Read, while Guest–Notes.txt contains None. The OS checks the requested operation against the corresponding cell and allows or denies it.
