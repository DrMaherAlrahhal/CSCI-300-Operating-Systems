1. From Processes to Threads

A process is a program in execution. A thread is a sequence of instructions that can execute within a process. Threads in the same process typically share its memory and resources, but each has its own execution state.

A process can contain several threads. Can multiple threads actually execute at the same instant? That depends on the available CPU cores.

2. Multicore Programming

A multicore CPU has more than one processing core. With multiple available cores, threads can execute in parallel. On one core, threads can still be concurrent by taking turns.

Interactive: One core vs two cores

Choose the number of CPU cores and assign three runnable threads.

Concurrency

Threads can make progress over overlapping periods, even by alternating on one core.

Parallelism

Two or more threads execute simultaneously on separate cores.

Cores are hardware resources. The OS also needs a way to connect application threads with the threads the kernel schedules.

3. Multithreading Models

Multithreading models describe how user-level threads are mapped to kernel-level threads.

Interactive: Select a model

Many-to-OneSeveral user threads map to one kernel thread. They cannot run in parallel on separate cores through that one kernel thread.
One-to-OneEach user thread maps to a kernel thread. Supports parallel execution on multicore hardware.
Many-to-ManyMany user threads are mapped over a set of kernel threads.

These models describe how threads connect to the kernel. How does a programmer create and control threads in code?

A thread library provides functions to create, manage, synchronize, and wait for threads. Common examples include POSIX Pthreads, Windows threading APIs, and Java threads.

5. Implicit Threading

With explicit threading, a programmer directly creates and manages threads. With implicit threading, a runtime or library manages much of that work, often using a pool of worker threads.

6. Threading Issues

Threads in one process may share variables. If two threads update the same variable without proper coordination, the result may be wrong. This is a race condition.

3 Short-Answer Questions

1. Explain the difference between a process and a thread. Give one example.

A process is a program in execution with its own resources. A thread is an execution path within a process. A browser process can use threads for its user interface, loading content, and downloads. Threads within the same process share resources such as memory.

2. Compare concurrency and parallelism. How do multicore CPUs help?

Concurrency means multiple tasks make progress during overlapping periods, potentially by taking turns. Parallelism means tasks actually execute at the same instant. Multiple CPU cores can execute different threads simultaneously.

3. What is a race condition? Explain using a shared counter.

A race condition occurs when the outcome depends on the order of unsynchronized operations. If two threads both read counter = 0 and each writes 1, the final result is 1 instead of 2. A lock or another synchronization mechanism can prevent this lost update.
