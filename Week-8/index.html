Deadlock: A group of processes cannot make progress because each is waiting for an event or resource that another waiting process must provide.

1. Deadlock in Multithreaded Applications

Threads in the same application may use multiple locks. If Thread A locks resource X and waits for Y while Thread B locks Y and waits for X, both can become stuck.

2. Deadlock Characterization

Four conditions must hold at the same time for a deadlock to be possible:

1. Mutual Exclusion

A resource cannot be shared by two processes simultaneously.

2. Hold and Wait

A process holds a resource while waiting for another.

3. No Preemption

The resource cannot simply be taken away by force.

4. Circular Wait

Processes form a cycle of waiting for each other.

Check the conditions

Uncheck any condition and see what it means for the classic four-condition deadlock scenario.

Important: All four are necessary, but having them present does not prove that every particular system state is deadlocked.

3. Methods for Handling Deadlocks

Prevention

Design the system so at least one necessary condition cannot hold.

Avoidance

Grant requests only when the resulting allocation remains in a safe state.

Detection + Recovery

Allow deadlocks to occur, find them, then take corrective action.

Ignore

Some general-purpose systems leave rare deadlocks to applications or users rather than guaranteeing global prevention.

Transition: The first strategy is to stop a deadlock from becoming possible.

4. Deadlock Prevention

Prevent deadlocks by ensuring at least one of the four necessary conditions cannot occur. For example, require processes to request locks in a fixed order: X before Y.

Choose a prevention rule

Trade-off: Prevention can limit concurrency or waste resources. Not every resource can be shared or safely preempted.

5. Deadlock Avoidance

Avoidance uses information about maximum resource needs to decide whether a new request keeps the system in a safe state. Banker's algorithm is a well-known example.

7. Recovery from Deadlock

After detection, the OS or application must break the deadlock. Common options include terminating a process, rolling one back, or preempting resources when safe and supported.

3 Exam-Style Questions

Question 1

Define deadlock and explain its four necessary conditions using two processes and two resources.

Deadlock occurs when processes are unable to proceed because they wait for one another. Four necessary conditions are mutual exclusion, hold and wait, no preemption, and circular wait. Example: P1 holds printer and waits for scanner, while P2 holds scanner and waits for printer.

Question 2

Compare deadlock prevention, avoidance, and detection with recovery.

Prevention breaks at least one necessary deadlock condition. Avoidance checks that each new allocation leaves the system in a safe state. Detection allows deadlocks to occur, identifies them, and recovery breaks the deadlock by termination, rollback, or suitable resource preemption.

Question 3

Two threads lock resources A and B in opposite orders. Explain the risk and propose a solution.

Thread 1 can hold A and wait for B while Thread 2 holds B and waits for A, creating circular wait and deadlock. Require both threads to acquire locks in the same order, for example A before B, to eliminate circular wait in this scenario.
